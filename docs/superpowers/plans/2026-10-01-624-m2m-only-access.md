# M2M-Only Access with On-Behalf-Of Identity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only M2M clients reach the cyoda-go API. An on-behalf-of (OBO) client exchanges an application-signed user assertion for a token that carries the user, and cyoda-go records that user and the executing client in entity history, audit events, callouts and messages.

**Architecture:** The OIDC subsystem, the key-pair `audience` concept and the trusted-key node copy are deleted. `spi.UserContext` gains `Executor`; `spi.AttributionFor` gains the OBO branch. The token endpoint is rewritten around stored client records (`OnBehalfOf`, `SecretGen`), with a verified-secret cache, a node-wide bcrypt bound and a per-client bucket. Every route requires `ROLE_M2M` except a named allow-list; compute streams require a client token and re-check their client every 60 s. Callouts carry an identity computed once on the dispatching node and forwarded on the wire.

**Tech Stack:** Go 1.26, `net/http` + chi, gRPC, oapi-codegen (`go generate ./api`), `golang.org/x/sync/semaphore`, `golang.org/x/time/rate` (new), testcontainers PostgreSQL E2E, cross-backend parity suite, cyoda-go-spi.

## Global Constraints

- Correctness over availability: an operation that cannot be completed correctly is refused; no fallback value stands in for a correct one (`.claude/rules/correctness-over-availability.md`).
- Tenant isolation on every data path; no response reveals another tenant's clients or keys.
- Never log a secret, token, assertion, or signing key at any level. OAuth error descriptions never echo the subject, the tenant or the key id.
- 4xx: domain detail with error code. 5xx: generic message plus ticket UUID.
- Exact values (copy verbatim):
  - OBO grant type: `urn:ietf:params:oauth:grant-type:token-exchange`; subject token type: `urn:ietf:params:oauth:token-type:jwt`.
  - Assertion: RS256 only; `exp − iat` ≤ 300 s; clock skew 30 s.
  - `CYODA_JWT_EXPIRY_SECONDS`: default `300`, range `1`–`3600`.
  - `CYODA_IAM_TOKEN_REQUESTS_PER_MINUTE`: default `600`, `0` = unlimited, negative refused at startup.
  - `CYODA_IAM_TOKEN_MAX_CONCURRENT_SECRET_CHECKS`: default `runtime.NumCPU()`, `≥ 1`.
  - Wait for a bcrypt slot: 1 s, then `503 temporarily_unavailable`, `Retry-After: 1`.
  - `CYODA_IAM_MOCK_KIND` default: `service`.
  - Stream re-check interval: 60 s (a constant, not configurable).
  - Reserved user id: `system`, case-insensitive.
  - New callout attributes: `authexectype`, `authexecid`.
  - New claim on client-credentials tokens: `cgen` (the client's `SecretGen`). OBO tokens carry `act: {"sub": "<client id>"}` and no `cgen`.
- Roles: plain client `[ROLE_M2M]`; admin client `[ROLE_M2M, ROLE_ADMIN]`; OBO client `[ROLE_M2M]`, `OnBehalfOf=true`, never `ROLE_ADMIN`, never in tenant `PLATFORM`.
- No issue ids (`#624`, `#80` …) in code, comments, help text, OpenAPI, error messages or logs. Commit messages, PR body and specs only.
- Go conventions: `log/slog` only; constructor DI; no test hooks or seams in production code; `fmt.Errorf("failed to X: %w", err)`.
- OpenAPI: edit `api/openapi.yaml`, then `go generate ./api`; never hand-edit `api/generated.go`.
- Every removed or added error code moves together with its `cmd/cyoda/help/content/errors/<CODE>.md` file and its line in `cmd/cyoda/help/content/errors.md` (`TestErrCode_Parity`, `TestErrorIndex_ListsEveryCode`).

## Rulings (decided while writing this plan)

Each ruling: what — why — what it costs if wrong.

1. **§5.5 applies at `txjoin.Joiner.join`.** The only way into a transaction is a callout's pass (`X-Tx-Token`), and the pass does not bind a caller. A compute node that presents the pass with an OBO token for another user would be recorded as that user inside the first user's transaction. The check runs after `txMgr.Join` and before the fence. — Cost if wrong: one extra refusal path on joined callbacks.
2. **Client-token marker lives in `internal/contract`** (`contract.ClientToken{ClientID string; Gen uint64}`, `contract.WithClientToken`, `contract.ClientTokenFrom`), set by the authentication service. `contract.AuthenticationService.Authenticate` returns the authenticated `context.Context` (with `UserContext` and, for a client token, the marker) instead of `*spi.UserContext`. The validator returns `(*spi.UserContext, *contract.ClientToken, error)`. — `contract` is a leaf package that both `internal/auth` and `internal/iam/mock` can import. Cost if wrong: signature churn in two callers.
3. **Verified-secret cache and bcrypt bound live inside `KVM2MClientStore.Authenticate`**, after the client record is read (so a reset or delete takes effect at once). Every bcrypt (real or burned) takes a slot from a `golang.org/x/sync/semaphore.Weighted`; waiting more than 1 s returns `auth.ErrSecretCheckBusy`, which the token handler maps to `503`. — The record read and the hash comparison are one decision; splitting them across a decorator would read the record twice. Cost if wrong: a refactor into a decorator later.
4. **Per-client bucket: `golang.org/x/time/rate`** (new dependency, Go team module) keyed by client id, one `*rate.Limiter` per client per node, `rate.Every(time.Minute/n)` with burst `n`. — A hand-rolled bucket is more code to get wrong. Cost: one new module in `go.mod`.
5. **OBO-in-PLATFORM and OBO-with-ROLE_ADMIN are refused at `POST /clients` only**, not re-checked in the store codec. — The handler is the only creator; a second check would be an unreachable guard branch (project rule: delete unreachable branches).
6. **Callout identity is a field of `internalgrpc.Callout`** (`Identity CalloutIdentity{Attributed, Executor spi.Principal; Roles []string}`), set once in `callout.Coordinator.run` from `spi.AttributionFor(ctx)` and the caller's roles. The hand-over wire carries it; the peer's rebuilt `Callout` carries the received value; `AttachAuthContext` reads only `call.Identity`. — One value, read by both local and peer dispatch, never recomputed. Cost if wrong: none beyond the wire shape, which is internal and pre-1.0.
7. **Audit `executedBy` is added to the two leaf schemas** (`EntityChangeAuditEventDto`, `StateMachineAuditEventDto`), not to the shared base (system audit events have no executor). `AuditActorInfoDto` gains `kind`.
8. **`spi.MessageHeader` gains `AttributedKind PrincipalKind` and `Executor Principal`** (mirrors `EntityVersionMeta`); `UserID` is the attributed id. The message GET response adds `attributedKind` and `executedBy {id, kind}` beside `userId`.
9. **Chart `jwt.expirySeconds` schema becomes `minimum: 1, maximum: 3600`, default `300`** — the chart and the binary state one contract.
10. **Key-pair `KeyPair.Audience`, `KeyMeta.Audience` and the vault AAD field are removed.** The vault seals with the remaining fields; existing sealed records are invalid after this change, which is acceptable with no production instances. Every signing-key test that seals fixtures is re-run.
11. **Compute nodes in every test harness authenticate as real M2M clients** (Task 11): the fixtures create a client and the compute test client fetches and refreshes its own token with `client_credentials`. A self-minted compute token cannot pass the stream guard (no client record to re-check).
12. **`http_jwks_source.go` and `NewJWKSValidator` are deleted; their test users move to a map-backed `KeySource` test double** (`staticKeySource`) built with `NewValidatorFromSource`.
13. **`ProbeAuthRaw` moves to `e2e/parity/client/account.go` and probes `GET /api/account`**; the OIDC tenant-admin control case in `RunPlatformOperatorGate` is replaced by an OBO-token case (Task 12): a token exchanged in tenant T, with `user_roles: ["ROLE_ADMIN"]` and `caas_org_id: "PLATFORM"` in the assertion, is refused at the exchange (`403 access_denied`), and an OBO token of T is refused on every operator route (`403`).
14. **`internal/e2e/keys_trusted_reconciliation_test.go` is deleted after its still-valid cases move** (cap reached, bad key id, unknown id, out-of-range windows) to `internal/e2e/oauth_keys_test.go`.
15. **`TestAttribution_D3_OBOKeepsOwnUser` is rewritten for real OBO tokens:** a callback presenting an OBO token for the transaction's own user is admitted and attributed to that user with the OBO client as executor; for another user it is refused `403`.
16. **The SPI change is one cyoda-go-spi PR into `main`** (no tag mid-milestone). cyoda-go builds against it through an uncommitted `go.work` until the SPI PR merges, then pseudo-pins `main` in one commit (`make repin-plugins`). `context.go`:

```go
type UserContext struct {
	UserID   string
	UserName string
	Kind     PrincipalKind
	Tenant   Tenant
	Roles    []string
	// Executor is the M2M client that acts for UserID. It is set only for an
	// on-behalf-of token; nil for every other principal.
	Executor *Principal
}

// AttributionFor returns (attributed, executor) for a durable write staged
// under ctx. An on-behalf-of principal attributes to its user and executes as
// its client, and never inherits a transaction's origin. Otherwise origin
// inheritance engages only for service/system executors inside a transaction;
// a user-kind executor records itself.
func AttributionFor(ctx context.Context) (attributed, executor Principal) {
	uc := GetUserContext(ctx)
	if uc != nil && uc.Executor != nil {
		return Principal{ID: uc.UserID, Kind: uc.Kind}, *uc.Executor
	}
	if uc != nil {
		executor = Principal{ID: uc.UserID, Kind: uc.Kind}
	}
	if executor.Kind == PrincipalService || executor.Kind == PrincipalSystem {
		if tx := GetTransaction(ctx); tx != nil && tx.Origin != (Principal{}) {
			return tx.Origin, executor
		}
	}
	return executor, executor
}
```
