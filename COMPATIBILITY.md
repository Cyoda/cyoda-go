# Compatibility

Cross-repo version compatibility for the cyoda-go ecosystem.

The ecosystem has five independent SemVer axes, each tracking a different stability promise to a different audience. This file declares the supported combinations.

## The five axes

| Axis | What it tracks | Bumps when | Consumed by |
|---|---|---|---|
| **`cyoda-go` binary** `v<X.Y.Z>` | The shipped EDBMS application | Each user-facing release | End users (Homebrew, downloads, Docker) |
| **`cyoda-go-spi`** `v<X.Y.Z>` | The stable plugin contract surface | The SPI Go interface changes | Storage-plugin authors (in-tree + out-of-tree) |
| **`cyoda-go/plugins/<x>`** `v<X.Y.Z>` | Each in-tree plugin's exported API | The plugin module's exported Go API changes | Out-of-tree plugin authors (test fixtures) |
| **Chart `version:`** | Helm chart's manifest output | Templates / values / schema change | Helm operators |
| **Chart `appVersion:`** | Default binary the chart ships | Each binary release worth advertising via the chart | Helm operators |

Coupled by the dependency direction:

```
cyoda-go-spi   ←   cyoda-go   ←   cyoda-go-cassandra (out-of-tree)
                       ↓
                   plugins/{memory,sqlite,postgres}
                       ↓
                   deploy/helm/cyoda  (chart)
                       ↓
                   homebrew-cyoda-go  (formula, auto-synced by GoReleaser)
```

Coordinated-release procedure documented in [`MAINTAINING.md`](./MAINTAINING.md).

## Compatibility matrix — `cyoda-go` × `cyoda-go-spi`

| `cyoda-go` | Root `go.mod` pins | In-tree plugin go.mods pin | SPI surface added in this release |

| **`v0.8.4`** _(planned)_ | `cyoda-go-spi v0.8.4` pseudo-version (tag pending at milestone-end) | same pseudo-version | **Relocation, not new surface**: `ConditionToFilter` and the model-schema read core move out of `cyoda-go/internal/domain/search` into the SPI, where a storage plugin can reach them. Added: `ConditionToFilter`, `FieldDescriptor`, `FieldsMapFromSchema`, `NormalisePath`, `MapOperator` / `LookupOperator` / `OperatorNames` / `ValidateConditionOperators` / `MaxConditionDepth`, `ClassifyType` / `ClassifyTypesFold`, `MetaField` / `ResolveMetaField` / `MetaFieldNames` / `IsTemporalMetaField`, and the `ErrUnknownOperator` sentinel. cyoda-go **deletes** its copies in the same change — the point is that exactly one implementation exists, because two drifted within days of the first attempt. The commercial backend is the reason this exists: it is the only backend that self-executes a search, its async path evaluates conditions with an evaluator of its own, and it cannot reach the shared kernel without this. It keeps working unchanged on `v0.8.3` and adopts when it converges that path. **Second breaking SPI change, same release**: `Filter.Prepare(Filter) PreparedFilter` and `(PreparedFilter).Match(data, meta) bool` replace `MatchFilter`, `EvalLeafString`, `evalLeafFast` and `Expansion.Void`, removed with no deprecation shim — the removal is what forces every caller to re-site preparation, so operand parsing, declared-type bucketing and `regexp.Compile` run once per query instead of once per candidate row. **A plugin doing its own per-row leaf evaluation must call `Prepare` once above its row-scan loop and `Match` inside it — not substitute `Prepare`+`Match` for the old call in place inside the loop**, or the same per-row cost reappears. Both SPI changes are merged as `cyoda-go-spi@aaddb33`; the pseudo-pin has since advanced to `cyoda-go-spi@f746c12`, which adds conformance-only surface (no new interfaces): `spitest` now requires `GetSubmitTime` to enforce tenant isolation (`TxStateErrors/TenantMismatchOnGetSubmitTime`, `TxStateErrors/NotFoundOnGetSubmitTime`) — a backend that ignores the method's `ctx` fails conformance until it adds the gate; the commercial backend picks this up (and must conform) on its next spitest bump. **Third wave, same release**: the pseudo-pin has advanced again to `cyoda-go-spi@727dd65` — the merged streaming-search-store surface (spec: `docs/superpowers/specs/2026-08-22-472-search-spi-surface-design.md`). `AsyncSearchStore.SaveResults` and `UpdateJobStatus` both gain an `epoch int64` parameter, and `SaveResults` takes `iter.Seq[string]` instead of `[]string`; both now fence writes against a reclaim via two new sentinels, `ErrStaleClaim` and `ErrAlreadyTerminal`. Three new methods — `Heartbeat`, `ClaimStale`, `ClearResults` — round out the epoch-fenced claim/reclaim lifecycle a crashed executor's job needs to be recovered. `EntityStore` gains `GetPage` (an ordered, bounded paged read) and `GetVersionByTransaction` plus `GetVersionMetadata`/`EntityVersionMeta` (audit-trail metadata without the entity payload), and **loses `GetVersionHistory`** — removed outright, no deprecation shim. `IterateOptions` gains `OrderBy` and `TrackingRead` fields, matching `Searcher`'s existing strictly bounded-or-fail `Limit` contract (`Limit <= 0` is unbounded and MUST NOT be silently capped — unchanged from `v0.8.3`, restated here because the new `IterateOptions` fields make it directly relevant to `Iterate` callers too). The two ordered-merge helpers change together: `MergeBounded`'s `limit <= 0` "unbounded" mode is dropped (now a contract violation, an error) and the new `MergeOrdered` is the streaming replacement for that unbounded case. `spitest`'s conformance subtests were renamed to track the entity-store change (`GetVersionHistory/Ordering` → `GetVersionMetadata/Ordering`, plus new `GetVersionMetadata/*`, `GetVersionByTransaction/*`, and `GetPage/*` subtests) — a consumer's `Skip` map keyed on the old subtest names hard-fails on the stale key rather than silently no-op-ing, so the commercial backend must update its skip list (and implement the new methods) on its next spitest bump, not just recompile. **Fourth wave, same release**: the pseudo-pin has advanced again to `cyoda-go-spi@5639cff`, which adds one exported symbol and eight conformance subtests. `ErrInvalidFilterPath` is promoted from three package-local plugin sentinels into the SPI, so a malformed path is classifiable rather than merely non-nil — the engine relies on that classification to tell "invalid input, reject 400" from "valid but not pushdownable, fall back to in-memory", and without it a rejection silently degrades into a fallback. That engine half is now implemented, not merely intended: `search.ClassifyStoreQueryError` maps the sentinel to **400 `INVALID_FIELD_PATH`**, and it is applied on **both** store branches — the bounded `Search` call and the unbounded `Iterate` drain. The `Iterate` branch previously had no classification at all, so the identical malformed input answered 400 or 500-with-a-ticket depending only on whether the request carried a positive `limit`. `ConditionToFilter` now **requires** JSON Path nomenclature on the wire form: a condition's `jsonPath` must carry the `$.` leader, and a bare identifier (`amount`), an empty or trailing segment (`$..a`, `$.a.`), bracket-quoted access (`$['x']`, `$.a["b"]`) or a bracket spelling outside the two supported subscript forms (`$.a[`, `$.a]`, `$.[0]`, `$.a[]`, `$.a[-1]`, `$.a[0:2]`, `$.a[0,1]`, `$.a[?(@.x)]`, `$.a[ 0]`, and any character trailing a valid subscript such as `$.a[0]b` or `$.a[*]..b`) is rejected with an error wrapping that sentinel. Only **well-formed** array-subscripted paths — the wildcard `[*]` or a non-negative index — keep failing with a plain error that does **not** wrap it (`$.tags[*].name`, `$.arr[0]`, `$.matrix[*][*]`, `$.orders[*].lines[*].sku`); that remains the fall-back-to-in-memory signal, deliberately. The classifier scans the whole path rather than stopping at the first `[`, which is what moved the malformed-subscript class from "unpushdownable, fall back" to "invalid, 400" — previously it fell back to an evaluator that resolves none of those spellings and answered 200 with an empty page. **This is a fourth obligation on the commercial backend**, alongside the three below, for any backend that validates filter paths itself: the malformed-subscript class must be rejected with an `errors.Is(err, spi.ErrInvalidFilterPath)`-satisfying error, and the well-formed class must NOT be, or working subscript queries turn into 400s. Note the two path forms are now documented as distinct and must not be conflated: the **wire** form requires the leader, while the plugin-facing `Filter.Path` is post-strip and **bare** (a `$.`-prefixed `Filter.Path` is malformed). The eight new `spitest` subtests pin three contracts that in-tree backends had already drifted on — `SaveResults` fencing on epoch and terminal status even for an empty sequence; in-transaction point-in-time reads being committed-only across `GetAsAt`/`GetAllAsAt`/`GetPage(asAt)`/`Search(PIT)`/`Iterate(PIT)`; and the `Filter.Path` grammar being enforced at `Search` and `Iterate` for both field sources. **This lands three obligations on the commercial backend at its next spitest bump, not one**: implement the empty-sequence fence, make in-transaction PIT reads committed-only, and validate filter paths returning an error that satisfies `errors.Is(err, spi.ErrInvalidFilterPath)`. All three are conformance failures until met — a backend that returns an unclassifiable error for a malformed path now fails the suite rather than passing silently. **Fifth wave, same release**: the pseudo-pin has advanced again to `cyoda-go-spi@eeb1c72`. `LIKE` is no longer translated into a regular expression — it is matched directly as a glob (`like_pattern.go`), which changes behaviour on five points a translation gets wrong: `%` and `_` now match a **newline** (a translated `.`/`.*` does not without the dot-all flag, so stored values containing a newline silently failed to match); `\` escapes **any** following character, not only `%`, `_` and `\` (`\a` is a literal `a`; cyoda-go's own translator passed `\` through untouched, so `\d`/`\w`/`\b` reached the regex engine as CLASSES — `LIKE "\d"` matched any digit — and now match the literal character); a pattern ending in an unpaired `\` is now **invalid** (an error wrapping the new `ErrInvalidPattern`), where before it produced a regex that failed to compile and so never matched — and once the boundary adopted the export (below) it became a **400**, not an empty page; literal text compares **bytewise**, so an operand carrying invalid UTF-8 matches the byte-identical stored value instead of being transcoded to U+FFFD; and `_` advances by one **rune**, not one byte. No regex metacharacter has any meaning in a `LIKE` operand. `ValidateLeafPattern`, `ValidateConditionPatterns` and `ErrInvalidPattern` are **exported** so a boundary validator derives the same accept/reject set as the evaluator instead of hand-rolling a bare compile; `MATCHES_PATTERN` now requires a standalone parse **as well as** an anchored compile, so a pattern that parses bare but fails once anchored is rejected up front. **cyoda-go's own boundary now calls them** (`ab09aef`): a malformed `LIKE` or `MATCHES_PATTERN` operand is rejected as `400 INVALID_CONDITION` on sync search, async submit, grouped statistics and conditional delete, and as `400 VALIDATION_FAILED` at workflow import, on HTTP and gRPC alike — so requests that returned `200` with an empty page, or (for the unterminated-`\Q` family) a `200` and a job id that then went `FAILED`, now return `400`. The **evaluator is deliberately unchanged**: below the boundary an unexpandable operand is still a leaf that never matches, which is what `spitest`'s `Searcher/Pattern/MalformedLike` requires and what keeps workflow-criterion evaluation fail-closed on the one path that never crosses the boundary. A backend must not make its evaluator error on a malformed pattern. `ErrScanBudgetExhausted` is **deleted** from the SPI with no deprecation shim: bounding search time is the caller's, not the backend's, so no `Searcher` meters examined rows any more. cyoda-go removes its sqlite budget, the `CYODA_SQLITE_SEARCH_SCAN_LIMIT` variable and the `SCAN_BUDGET_EXHAUSTED` error code in the same change — a relaxation (requests that used to fail now succeed), and it closes the sqlite-vs-memory/postgres divergence in the backward-compatible direction. A backend that returned that sentinel must stop; there is nothing for it to return instead. See [`docs/cloud-parity/like-glob-grammar.md`](./docs/cloud-parity/like-glob-grammar.md). **This is a fifth obligation on the commercial backend**: it carries a second, divergent LIKE→regex implementation of its own, which fails the new `spitest` grammar case until it adopts the kernel — align the fork away, do not patch it. The five obligations accrued for its next `spitest` bump are therefore: (1) empty-sequence `SaveResults` fences on epoch and terminal status; (2) in-transaction point-in-time reads are committed-only; (3) filter-path validation returns an error satisfying `errors.Is(err, spi.ErrInvalidFilterPath)`; (4) malformed array-subscript syntax is rejected; and (5) LIKE grammar convergence on the kernel. All five are conformance failures until met. The in-tree memory, sqlite and postgres backends pass the new pattern subtests unchanged. **Sixth wave, same release**: the model-schema READ core the second wave relocated is now the ONLY one — `ModelNode`, its wire codec and the field flattening live in the SPI and cyoda-go aliases them, the way it already aliases `DataType` and `TypeSet`. This is a **bug fix, not tidiness**: the two copies had drifted. The SPI's decoder dispatched on a node's single `kind` label, so for a field observed as more than one kind it dropped the branches the label did not name — the array branch of an object-and-array union, the scalar branch of an array-and-scalar union — and a predicate on a dropped path then found no declared type and matched nothing. No error, just fewer rows, which is the exact failure mode `model_schema.go`'s own header warns about. **Breaking SPI surface**: `ModelNode.Kind()`, `.Types()`, `.Element()` and `.Children()` are replaced by `.Scalar()`, `.Object()`, `.Array()` — each returning that branch or nil — plus `.Kinds()`, `.Branch()`, `.IsPolymorphic()`, `.Nullable()`, `.DeclaredTypes()` and the mutators (`DeclareKind`, `AddScalarTypes`, `SetNullable`, `SetChild`, `SetElement`, `ObserveArrayWidth`) the engine builds a tree with; `ArrayInfo` is gone, its live half now `ArrayBranch.MaxWidth`. A node holds the SET of kinds it was observed as, because a single label could only ever name one of three independent payload slots. The **persisted format is unchanged for every monomorphic node**, nullable or not: `"kinds"` is written only by a node declaring more than one, both spellings are read, and a node stored under the old form restores every branch its payload carries — so there is no migration and no coordinated flag day. **This is a sixth obligation on the commercial backend**, and unlike the others it is a compile break rather than a conformance failure: any code calling the removed accessors must move to the branch ones on its next pin bump. A backend that only passes `ModelDescriptor.Schema` to `FieldsMapFromSchema` needs no change beyond the rebuild — and gains the fix, since the dropped branches come back. The sixth wave is pinned as `cyoda-go-spi@82d5096`. That pin also picks up two SPI commits that landed after `eeb1c72` and were therefore in no earlier pin. **[spi#44](https://github.com/Cyoda/cyoda-go-spi/pull/44)** widens `spitest`'s `filterPathRejects` table to cover `?`, `#`, `|` and `!` — the metacharacters whose acceptance by a backend is not an empty page but the WRONG one, measured against gjson: `a?b` is answered by a sibling key `aXb`, `a|b` by a nested a→b, `arr.#` by the element count, and `!true` by the literal `true` whatever the document holds. Conformance-only, no new interfaces; it sharpens obligation 3 below rather than adding an obligation of its own. **[spi#45](https://github.com/Cyoda/cyoda-go-spi/pull/45)** is godoc only — `SearchJob.Condition` keeps domain syntax permanently, and a self-executing store translates it with `ConditionToFilter`/`FieldsMapFromSchema` and evaluates with the kernel — so it changes no surface. The sixth wave itself also carries a follow-up: `ObserveArrayWidth` was the one mutator that did not drop the cached flattening, and `maxWidth` reaches `FieldDescriptor.MaxWidth` — no caller reads `Fields()` before setting the width, so it was a latent trap rather than a live bug, but it is one a plugin holding the type could have hit. **Seventh wave, same release**: the path-grammar-and-resolver rewrite (`docs/cloud-parity/path-grammar.md`, `docs/cloud-parity/operator-semantics.md`), merged as [spi#49](https://github.com/Cyoda/cyoda-go-spi/pull/49) (`299da8e`) and pinned by all four in-tree `go.mod` files. Two files are new: `filter_path.go` (`ParseFilterPath`/`ValidateFilterPath`, `PathHop`/`PathSub` — one filter-path grammar, bracket subscripts included) and `filter_path_resolve.go` (`ResolvePath` — the one resolver the SPI kernel's `PreparedFilter.Match` and the engine's in-memory fallback evaluator now both call, so a pushed-down query and a residual re-check cannot disagree). `arrayToFilter` is deleted; an `array` clause desugars into an `AND` of positional comparisons instead, at one call site both entry points share. This is a **seventh obligation on the commercial backend**, alongside the six above, and it is different in kind from the others: it is not a compile break or a conformance-suite gap, it is work a self-executing backend must implement itself rather than inherit through shared code, per `path-grammar.md` section 12: (a) **path resolution for every form** — bare, positional, wildcard — decided by the field's *declared* shape, never by the shape of the stored value; (b) **the declared-type lookup**, including the fold from a positional path to the wildcard model key a schema records an array's element under; (c) **the field-existence check** of section 6, including the container-path rules (a structural path carries no scalar comparison); (d) **the filter-path grammar** of section 9, including the bracket subscript forms and the `ErrInvalidFilterPath` rejection sentinel, kept distinct from a well-formed-but-untranslatable path. The cross-backend parity suite (`e2e/parity/path_addressing.go`, registered in `e2e/parity/registry.go`) now checks these on every backend wired into it, so a backend that has not implemented them fails on its next dependency update rather than diverging silently. **Eighth wave, same release**: [spi#50](https://github.com/Cyoda/cyoda-go-spi/pull/50) (`99b0b81`), three findings from a security review of the seventh. The load-bearing one narrows the grammar the seventh wave widened: a positional subscript's digit run must fit an **int32**, not Go's `int`. An index in `[2^31, 2^63)` cleared every validator and rendered as `doc->'a'->>2147483648` on PostgreSQL, which rejects the operator at parse (`operator does not exist: jsonb ->> bigint`); unclassified by the engine's store-error mapper, that answered **500 with a support ticket rather than 400**, on demand, from any authenticated user, on every search, iterate and grouped-stats request. It was also a cross-backend divergence — SQLite answered an empty page and the in-memory kernel non-matched — and platform-dependent, since a 32-bit build would have rejected it cleanly. int32 is the intersection every backend can address. `spitest`'s `filterPathRejects` carries an int32-overflowing index, so **this sharpens obligation (d) below rather than adding an eighth**: a backend that accepts such an index fails conformance. Also in this wave, both engine-side and needing nothing of a backend: an empty leaf `Filter.Path` resolved to the whole document instead of nothing, and `DesugarCondition` ran once per ancestor level instead of once. **Ninth wave, same release**: negation. `cyoda-go-spi#32` (an array-wildcard quantifier) is **dropped** — its premises were false as of `de71289`, and what remained of it (element correlation) is a capability gap the design records rather than closes; see `docs/superpowers/specs/2026-08-30-not-node-design.md` §12. `cyoda-go-spi#46` (a `NOT` group operator) is implemented: `spi.Filter` gains `FilterNot`, a branch node with exactly one child and an empty `Path`, giving `NOT` universal-quantifier semantics over a wildcard-addressed leaf (`NOT($.tags[*] EQUALS "red")` means no element equals `"red"`, distinct from the negative twin `$.tags[*] NOT_EQUAL "red"`, which means some element differs). `Prepare` rejects a malformed `FilterNot` — `Children` of length 0 or ≥ 2, or a single zero-`Op` child — rather than guessing an interpretation. **Third breaking SPI change, same release**: `Prepare` and `prepareNode` gain an error return; four causes that used to become a silently never-matching leaf now reject instead — an operand fitting no declared type, a `SourceData` or `SourceMeta` leaf path that is empty or outside the grammar, an unsupported operator (including a zero-`Op` leaf), and an uncompilable `LIKE`/`MATCHES_PATTERN` pattern. This is the prerequisite `NOT` needs: a leaf that silently never-matches is safe under `AND`/`OR` alone, and unsafe the moment a `NOT` can invert it into matches-everything. Every in-module caller updated for the second return value; the ripple crosses module boundaries too — `spi.Prepare` has seven non-test call sites across the three in-tree plugins (`memory/searcher.go`, `memory/grouped_stats.go` (×2), `sqlite/searcher.go`, `sqlite/query_planner.go`, `sqlite/grouped_stats.go`, `postgres/query_planner.go`), all updated in lock-step in this same milestone. `groupToFilter` no longer folds an unrecognised operator into `FilterAnd`: the wire `operator` is matched exactly against the closed set `{AND, OR, NOT}`, and anything else — including a case variant such as `"and"` — fails with `ErrUnknownOperator` rather than silently becoming a conjunction. **`spitest`'s `Searcher/Pattern/MalformedLike` case is inverted**: a malformed `LIKE` operand now requires an error from `Search`, not an empty page — the same reasoning eighth wave's own int32 bound rests on: the request boundary already refusing a case is a reason it should be unreachable underneath, never a reason to require the wrong answer there. Two new `spitest` cases — `Searcher/FilterNot` and `Iterable/FilterNot` — make `FilterNot` a conformance requirement for a self-executing backend, not merely advice, and the existing nested-malformed-path case gains a `NOT`-nested variant so a validator that recurses on a fixed `{AND, OR}` case list rather than "this node has children" is caught. **This wave lands five obligations on the commercial backend, per `docs/superpowers/specs/2026-08-30-not-node-design.md` §14**: (1) validate filter paths through a `NOT` node, the same recursion the spitest nested-malformed-path variant above requires; (2) evaluate `FilterNot` if it self-executes searches — exactly one child, inverting a two-valued result, failing rather than matching for a malformed node — which the two new `Searcher/FilterNot`/`Iterable/FilterNot` spitest cases above make a conformance requirement, not merely advice; (3) do not push a `NOT` into a query unless every leaf beneath it translates exactly — leaving it residual is always correct, the same rule cyoda-go's own two SQL planners follow below; (4) `Search` fails on an unevaluable operand rather than returning an empty page, classified so it surfaces as `400` and not `500` — the inverted `MalformedLike` case above is one instance of this; and (5) answer an unsatisfiable comparison by operator polarity, per stored-value type family, rather than false for every operator — the same rule cyoda-go's own fix below applies. All five are conformance failures until met at the backend's next `spitest` bump. On the cyoda-go side, in the same milestone: an unsatisfiable comparison now answers by operator polarity per stored-value type family rather than always false (`$.n NOT_EQUAL 12.5` on an `INTEGER` field now matches every entity holding a number, matching PostgreSQL) — this widens conditional delete as well as search, since `DELETE /entity/{name}/{version}` evaluates its condition through the same kernel, so a stored or scheduled delete using a negative operator against a typed field now removes strictly more rows after upgrade; entities missing the field or holding an explicit `null` there are unaffected, because those still fail closed for every binary operator, negatives included; a workflow criterion naming a field the model does not declare now aborts and rolls back the transition's save at evaluation time, checked with the same `search.ValidateKnownPaths`/`ValidateConditionValueTypes`/`ValidatePatterns` calls a search condition already applies; all three in-tree plugins' filter-path validators recurse into `FilterNot`'s subtree (previously only `AND`/`OR`, silently skipping a `NOT`'s child); and neither SQL planner pushes `NOT` down — it is residual by construction, pinned by a planner test so a later `isPushable` change cannot make it pushable without the soundness rule being written first. See `docs/cloud-parity/negation.md`, `docs/cloud-parity/operator-semantics.md`, `docs/cloud-parity/path-grammar.md` and `docs/cloud-parity/unevaluable-criterion-fails-save.md`. **No SPI tag is cut for this wave either** — it merges to `cyoda-go-spi` `main` and is recorded in its own `CHANGELOG.md`'s `[Unreleased]` section; the pin bump across all four `go.mod` files happens in a later, separate step, alongside removing the local `go.work` `use` line. **The current pin is `cyoda-go-spi@v0.8.4-0.20260830161031-99b0b81c4322` across all four `go.mod` files — the ninth wave above is merged to the SPI feature branch but not yet pinned.** `cyoda-go-spi#32` is dropped, not outstanding. Only the real `v0.8.4` tag (cut at milestone-end, not per-PR) and the pin bump that both merges the ninth wave to SPI `main` and replaces the pseudo-versions with the resulting commit are outstanding. Also in this release: the transaction-lifecycle work adds `503 STORAGE_UNAVAILABLE`, which a backend opts into structurally via `interface{ StorageUnavailable() bool }` matched with `errors.As` — no SPI declaration needed. The streaming-search work adds two more reachable statuses, both engine-side and needing no SPI declaration: `503 SEARCH_QUEUE_FULL` (retryable) on async-search submit, raised either when the node's bounded worker pool and its queue are both full or when one tenant exceeds `CYODA_SEARCH_ASYNC_MAX_PER_TENANT` in-flight jobs on that node; and `409 DELETE_NOT_CONVERGED` (retryable) on `deleteEntities`, raised when a batched conditional delete cannot converge because entities matching the condition are being created as fast as they are removed — a request that previously ran until the caller's context expired now fails closed with a diagnosable code. Chart `version:` / `appVersion:` and out-of-tree pin guidance are unchanged. ### Independent version axes

`cyoda-go` and `cyoda-go-spi` version **independently**. The binary pins the SPI version it needs and never skips or burns a version number to mirror the SPI's — this matrix is the source of truth for which binary pins which SPI, not a shared digit. `cyoda-go-spi` is the one axis that does **not** use the minor as its breaking-change signal ([README — Versioning](./README.md#versioning)). It is effectively an internal library — its only consumers are the in-tree plugins and the commercial Cassandra backend, all released in lock-step — so it ships breaking interface changes in patches rather than burning a minor for an audience of two. Read its `### Breaking` changelog section on every bump. The SPI was strictly additive throughout `v0.5.0…v0.8.2`; `v0.8.3` is its first breaking release.

Two repo-internal rules still hold and must not be confused with a binary↔SPI coupling: **pin-sync** (root + every `plugins/*/go.mod` agree on one SPI version, CI-gated by `make check-spi-pin-sync`) and **plugin-tag-equals-umbrella** (plugin submodule tags match the `cyoda-go` tag). Both are release hygiene *within* this repo; neither ties the binary's version number to the SPI's.

### Out-of-tree plugin authors

A plugin pinned to **`cyoda-go-spi v<X.Y.Z>`** is compatible with any **`cyoda-go v<A.B.C>`** whose root `go.mod` pins the same `v<X.Y>.*` series or any *later* `v<X+1.0.0>` series that hasn't broken the interfaces the plugin uses.

In practice, today: **all SPI versions `v0.5.0` … `v0.8.1` are mutually source-compatible** (additive changes only). Plugins on any of these versions build and run correctly against `cyoda-go v0.7.x` and `v0.8.1`. `cyoda-go-spi v0.8.3` breaks this: its bounded-or-fail `Searcher` contract removes `SearchOptions.Offset` and renames `MergePage` to `MergeBounded`, so a plugin pinned to any version below `v0.8.3` — including the additive `v0.8.2` — must be migrated (see the matrix row above) before it builds against `v0.8.3` or later.

### Migration window

cyoda-go's root `go.mod` may pin a **newer** SPI version than out-of-tree plugins are using. Consumers compose at runtime — the active plugin's pinned SPI version determines which SPI surface is actually exercised, and unused additions are inert. There is no requirement that the binary's SPI pin and the plugin's SPI pin match exactly.

### v0.8.3 milestone — SPI pin

Through the v0.8.3 development milestone the root `go.mod` and every in-tree plugin submodule pinned a **pseudo-version** of `cyoda-go-spi` while the `ScheduledTaskStore` surface, the arm-time Function additions (`TransitionSchedule.Function`, `ReconcileRequest.Cancel`), the Cloud-aligned type-directed search kernel (`DataType`/`Decimal`/`IsAssignableTo`, `ExpandLeaf`/`EvalLeaf`), and the bounded-or-fail direct-search change (`Searcher.Search`, `MergePage` → `MergeBounded`, `SearchOptions.Offset` removed — see `docs/cloud-parity/direct-search-bounded-or-fail.md`) landed. The pseudo-version advanced as milestone work merged — not per PR, only when a dependent change needed the newer SPI surface to build.

That window is **closed**: all four manifests now pin the real **`cyoda-go-spi v0.8.3`** tag, cut per the coordinated-release procedure in [`MAINTAINING.md`](./MAINTAINING.md). The tag is breaking despite being a patch — this module ships breaking changes on patches (see [Independent version axes](#independent-version-axes)), and its `### Breaking` changelog section rather than the version component is what flags it.

### Why there is no `v0.8.0` (SPI or binary)

A `cyoda-go-spi v0.8.0` tag was cut prematurely on 2026-06-13 at an incomplete
commit and was fetched through `proxy.golang.org`, which **permanently** binds a
version to the first commit it serves. A Go module version cannot be re-cut once
the proxy/checksum-database has seen it, so `v0.8.0` is abandoned and
**`cyoda-go-spi v0.8.1`** is the canonical, complete v0.8.x SPI release — it
resolves cleanly through the public proxy with no `GOPRIVATE` workaround. At the
time, `cyoda-go` also skipped `v0.8.0` to keep its number aligned with the SPI's
and shipped **`v0.8.1`**. That number-matching is **no longer policy** — the
binary and SPI now version independently (see [Independent version axes](#independent-version-axes)),
so a future poisoned SPI tag would not force the binary to skip a number. See
[`MAINTAINING.md`](./MAINTAINING.md): a module version is tagged exactly once, at
the final commit, and never re-cut.

### Optional capability interfaces (grouped-stats)

The `Iterable` and `GroupedAggregator` SPI interfaces are **type-assertion-only**. The `EntityStore` base interface is unchanged. Existing plugins keep compiling without implementing either. A plugin that implements neither causes `POST /api/entity/stats/{entityName}/{modelVersion}/query` to return 501 `NOT_IMPLEMENTED_BY_BACKEND`; every other endpoint continues to work normally. Implementing only `Iterable` is sufficient — the service layer falls back to streaming-tally when `GroupedAggregator` is absent. Implementing `GroupedAggregator` without `Iterable` is supported but loses the in-transaction code path (in-tx calls route through `Iterable` to preserve read-your-writes).

## Homebrew formula

[`homebrew-cyoda-go`](https://github.com/cyoda/homebrew-cyoda-go) ships a single binary per release. The `cyoda.rb` formula is auto-updated by GoReleaser on every `v*` tag push and pins:

- `version "<X.Y.Z>"` (matches the binary tag)
- `url "…/cyoda_<X.Y.Z>_<os>_<arch>.tar.gz"`
- `sha256 "…"` per platform

End users always get a coherent install — the formula's `version` IS the binary's version. There is no separate compatibility concern at this layer.

## Reading this matrix

- **End user installing or upgrading the binary**: care about the binary version only. Use Homebrew, the GitHub Release archives, or the Helm chart with `appVersion`.
- **Helm operator**: care about chart `version:` for upgrades and `appVersion:` for which binary you're deploying. Read the "Operator action required" table when bumping `appVersion:`.
- **Out-of-tree plugin author**: pin `cyoda-go-spi` at the version whose surface you use. The matrix tells you which `cyoda-go` binary versions ship a compatible engine.
- **Downstream Go-module consumer**: the binary's pinned SPI version is whichever the root `go.mod` declares for that release. The plugin submodule pins are independent — they apply only if you're consuming a submodule directly.

## Maintaining this file

Update on every cyoda-go binary release **and** on every cyoda-go-spi tag. The release-manager workflow in [`MAINTAINING.md`](./MAINTAINING.md) includes this file in the release checklist.

When the SPI introduces a breaking interface change (not planned in v0.x), add a "Breaking" row to the matrix and document the migration path in [`CHANGELOG.md`](./CHANGELOG.md).
